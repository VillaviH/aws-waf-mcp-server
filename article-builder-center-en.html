The Problem: WAF Logs Nobody Reads

If you have AWS WAF protecting your applications, you know it generates thousands of events per hour. Every blocked request, every triggered rule, every suspicious IP — all of it gets logged to S3. The problem is that nobody reads them.

The reality in most teams is this: WAF logs pile up in S3, you pay for the storage, and they only get reviewed after an incident has already happened. By then, the attacker is long gone — or worse, already inside.

⚠️
The Real Problem

In a typical day analysis (May 7, 2026), we found 839 requests targeting .env files — of which 775 were ALLOWED by the WAF. That means potentially 775 credential theft attempts slipped through unblocked.

The traditional approach requires: downloading the logs, decompressing them, writing Athena queries or Python scripts, interpreting the results, and repeating the whole process every time you want a different answer. It is tedious, slow, and requires specialized technical knowledge.

What if you could simply ask your AI assistant: "What attacks did you detect today?" and get a full analysis in seconds? That is exactly what aws-waf-logs MCP Server does.

🤖

What is the Model Context Protocol (MCP)?

The Model Context Protocol (MCP) is an open standard created by Anthropic that allows language models (LLMs) to connect with external tools in a standardized way. Think of it as a "universal API" that lets AI use your systems.

💡
Simple Analogy

If LLMs are the brain, MCP is the nervous system that lets them move their hands (execute tools), see (read files), and listen (query APIs).

With MCP, you can create a server that exposes specific functions from your infrastructure, and any compatible client (Claude Desktop, Amazon Q, Kiro IDE, etc.) can invoke those functions naturally, within a conversation.

The flow is simple:

  1. The user asks a question in natural language to the AI assistant
  2. The LLM identifies which MCP tool it needs to use
  3. The MCP server executes the function and returns the results
  4. The LLM interprets the results and responds to the user
🏗️

System Architecture

The MCP server acts as an intermediary between the AI agent and the AWS WAF logs stored in S3. The architecture is deliberately simple: no databases required, no additional infrastructure needed, and it works with the AWS credentials you already have configured.

El servidor se ejecuta localmente en tu máquina. Cuando el agente de IA necesita analizar logs, invoca las herramientas del servidor MCP, que a su vez usa boto3 para descargar los archivos desde S3 y los procesa en memoria. Los resultados se devuelven como texto estructurado que el LLM puede interpretar.

✅
No Additional Infrastructure

No Athena needed, no Elasticsearch, no additional services required. Just Python, your AWS credentials, and the MCP server running locally.

🛠️

El servidor expone 11 tools organizadas en tres categorías: descarga de logs, análisis, e investigación forense.

Installation and Setup

Installation takes less than 5 minutes. You only need Python 3.10+, configured AWS credentials, and your preferred MCP client.

1

Clone the repository

Download the MCP server code from GitHub.

bash 
git clone https://github.com/tu-usuario/aws-waf-mcp-server.git
cd aws-waf-mcp-server
2

Create virtual environment and install dependencies

Using a virtual environment is recommended to isolate dependencies.

bash 
python3 -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate

pip install mcp boto3 python-dotenv
3

Configure AWS credentials

The server uses the AWS profile configured on your system. Make sure you have read permissions on S3.

bash 
# Verify you have access to the logs bucket
aws s3 ls s3://tu-bucket-waf-logs/ --profile default

# Minimum required IAM policy:
# s3:GetObject, s3:ListBucket on the logs bucket
4

Configure the MCP client

Add the server to your MCP client configuration. Here is the example for Claude Desktop and Kiro IDE:

json — mcp.json 
{
  "aws-waf-logs": {
    "command": "/ruta/a/venv/bin/python3",
    "args": ["/ruta/a/aws-waf-mcp-server/server.py"],
    "env": {
      "AWS_PROFILE": "default",
      "AWS_REGION": "us-east-1"
    },
    "disabled": false,
    "autoApprove": [
      "analyze_waf_logs",
      "get_blocked_requests",
      "search_by_ip",
      "search_by_uri",
      "get_rule_details"
    ]
  }
}
💡
autoApprove

Tools in autoApprove run without asking the user for confirmation. It is recommended to include only read tools (not bulk download ones).

5

Verify the installation

Restart your MCP client and verify the server appears as available.

bash 
# Test the server directly
python3 server.py

# You should see:
Starting aws-waf-logs MCP Server...
Registered 11 tools
Server ready on stdio

Implementation Details

The server is built with the official MCP SDK for Python. Each tool is a function decorated with @mcp.tool() that receives typed parameters and returns structured text.

python — server.py (fragmento) 
from mcp.server.fastmcp import FastMCP
import boto3, gzip, json

mcp = FastMCP("aws-waf-logs")

# Tool de análisis de día completo
@mcp.tool()
def analyze_full_day(directory: str) -> str:
    """Analiza TODOS los archivos de logs en un directorio.
    Genera reporte consolidado con totales, reglas, IPs,
    países, dominios y tráfico por hora."""

    total = blocked = allowed = 0
    rules = {}
    countries = {}
    hourly = {}

    for file in Path(directory).glob("**/*.gz"):
        with gzip.open(file) as f:
            for line in f:
                log = json.loads(line)
                total += 1
                action = log.get("action", "")

                if action == "BLOCK":
                    blocked += 1
                    # Extraer regla que bloqueó
                    for rule in log.get("terminatingRuleMatchDetails", []):
                        name = rule["terminatingRuleId"]
                        rules[name] = rules.get(name, 0) + 1
                else:
                    allowed += 1

    block_rate = (blocked / total * 100) if total > 0 else 0

    return format_report(total, allowed, blocked, block_rate, rules, countries)

FastMCP vs base MCP SDK

The server uses FastMCP, a high-level layer on top of the MCP SDK that greatly simplifies tool definition. With a simple @mcp.tool() decorator, FastMCP automatically generates the JSON schema, handles serialization, and registers the tool with the server.

Conclusion

The aws-waf-logs MCP server transforms the way we interact with security logs. What previously required hours of manual work — downloading logs, writing scripts, interpreting results — now happens in seconds with a natural language question.

The May 7, 2026 analysis demonstrated the real value: in minutes we identified a critical gap (775 .env file requests allowed) that would otherwise have gone unnoticed among the thousands of events that day.
